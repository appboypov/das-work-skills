# Guided onboarding

Read [workflow](../workflow/SKILL.md). Explain each artifact and action as the user encounters it. Use a small meaningful change in the actual project rather than an invented feature.

1. Inspect setup through [setup](../setup-work-skills/SKILL.md). Confirm runtime, schema, Linear access, planning root, intent folder and single brain folder. Ask before initializing missing project configuration.
2. Find a small user-approved outcome by reading source and discussing the observed need. Resolve its owning intent through [intent context](../workflow/SKILL.md#intent-context). Explain how [explore](../openspec-explore/SKILL.md) investigates without implementing. Resolve behavioral questions with [grilling](../grilling/SKILL.md).
3. Use [propose](../openspec-propose/SKILL.md) to create the change and its proposal, specification deltas, design and tasks. Show their real locations and how dependencies control artifact readiness. Explain [new](../openspec-new-change/SKILL.md), [continue](../openspec-continue-change/SKILL.md) and [fast-forward](../openspec-ff-change/SKILL.md) as alternative planning entry points.
4. When issue creation is part of the exercise, use [to-tickets](../to-tickets/SKILL.md) and the matching Linear template. Show the link from the change to the issue. Explain that meaningful follow-up comments carry progress while its original brief remains intact.
5. Present the completed plan and obtain implementation approval. Then use [apply](../openspec-apply-change/SKILL.md) for the real implementation and behavioral checks. Explain the distinction between artifact readiness, checked tasks and execution evidence.
6. Use [verify](../openspec-verify-change/SKILL.md) to check conformance. Fix authorized findings through apply and repeat affected checks. Show how [update](../openspec-update-change/SKILL.md) revises planning and reconsiders completed tasks when requirements change.
7. When authorized and eligible, use [sync](../openspec-sync-specs/SKILL.md) and [archive](../openspec-archive-change/SKILL.md). Read the resulting current specification, archived change and ingested brain records. Explain how [bulk archive](../openspec-bulk-archive-change/SKILL.md) handles several changes, overlapping capabilities and individual ingestion outcomes.
8. Finish with the actual outcome, source changes, checks, Linear links, intent path, planning paths and brain record paths. Report any incomplete ingestion with its resumable archived identity. Offer [stores](../openspec-store/SKILL.md) and [worksets](../openspec-workset/SKILL.md) when the user needs multi-repository planning.
