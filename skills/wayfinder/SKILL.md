# Wayfinder

Read [workflow](../workflow/SKILL.md), [linear](../linear/SKILL.md), [grilling](../grilling/SKILL.md) and [domain-modeling](../domain-modeling/SKILL.md).

1. Establish the destination in the user's terms. Identify the questions that prevent a buildable specification. If the route is already clear, continue with [to-spec](../to-spec/SKILL.md).
2. Keep a decision map in the change or a linked Linear document. It names the destination, settled decisions with links, unresolved questions and scope boundaries. Use existing initiative or project structure when the effort warrants it.
3. Create bounded decision work only for questions precise enough to investigate now. Use the applicable issue or action template through linear. Native dependencies express which answers unlock which questions. Assign work to an actual authorized workspace member when applicable.
4. Resolve a ready question through research, prototype or questioning. Human decisions come from the user; factual research can run directly. A human-only prerequisite gets an actionable brief. Save the answer in its owning artifact and add a short meaningful issue comment.
5. Update the map with links and newly unblocked questions. A rejected direction retains its reason in history. Keep the destination's scope explicit as the map evolves.
6. When material questions are settled, hand the map and its supporting decisions to to-spec, then to-tickets. A clear decision map establishes planning readiness rather than implementation permission.
